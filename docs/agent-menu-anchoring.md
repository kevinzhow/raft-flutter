# Agent menu anchoring and input

An Agent overflow menu stayed at its untransformed layout position when the Brutal trigger moved on hover. Its full-screen dismissal detector also intercepted hover over the trigger. The React visual provider clicks with a mouse and leaves the pointer on that button; the Flutter fixture used a touch tap, so it missed both behaviors.

The real Source DOM measured a 62px panel header and a 28px trigger with layout top 16px. Hover applies the recipe's `translate: 0px -1px`, moving its painted top to 15px. The Source popup starts at 47px: transformed trigger bottom 43px plus the declared 4px offset. The layout dimensions were already correct; no header offset was added.

`RaftPanelIconButton` can now attach an overlay anchor inside its recipe transform. `RaftOverflowMenuButton` uses that painted anchor and grouped `TapRegion`s instead of a detector covering the trigger. Outside taps dismiss without activating underlying controls; trigger and menu taps stay in their group. Pointer opening focuses the menu's keyboard receiver without selecting its first item. Keyboard and semantics activation focus the first item. Escape closes and restores trigger focus, and Enter can reopen and activate an item. The control's existing pointer, touch, recipe and disabled behavior remains available; `RaftInteractive` falls back to its ordinary callback when no distinct keyboard/semantics callback is supplied.

The Flutter parity fixture now performs the same mouse click as the unmodified Source provider and retains hover until capture. All 99 React PNGs remain byte-identical. Source product files, visual thresholds and case identities are unchanged. This brings the original Agent menu from 95.862% to 96.385%, and the unchanged 99-case matrix to **79 passing / 20 different / no capture errors or missing cases**.
