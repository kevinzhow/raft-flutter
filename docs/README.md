# docs/ index

Every file or directory under `docs/` is listed here (path — what it is — when to read it); `tool/tests/test_docs_index.py` fails the gate otherwise. Verification evidence (commands, results, devices, screenshots) goes in the PR description, not in `docs/`. Add a doc only for a rule or procedure someone will need later, and list it here.

## Start here

- `architecture.md` — layers, ownership, navigation, stable rules (logout policy, edge-to-edge, retained pages) — before changing structure or session/navigation behavior.
- `controller-clusters.md` — field/member clusters of `WorkspaceController` with proposed repository owners, extraction order and the first slice plan (generated inputs: `tool/controller_clusters.py`) — before splitting the controller or adding state to it.
- `development.md` — setup, run, test, merge gate, behaviour-parity checklists, branches — before your first change.
- `parity.md` — visual parity harness and every intended difference from Web — before touching pixels or a parity case.
- `parity-coverage-map.md` — every Web v1.21.23 surface with its level (frame / page / component), cases, widths, modes and score (generated by `tool/parity-ext/coverage_map.py`) — when asking whether a surface is covered.
- `parity-ext-quickstart.md` — add or fix an extension parity case — when working in `tool/parity-ext`.
- `parity-and-alignment.md` — page coverage, alignment tooling — when checking a page against Web.
- `parity-review.md` — client-wide parity review and open gaps — when asked what is not at parity.
- `capability-parity.json` / `capability-parity.md` — every Web call and capability with Flutter status (md is generated by `tool/capability_parity_report.py`) — before porting a feature.
- `feature-parity.csv` — per-module platform status matrix (input of `tool/publish-report`) — when reporting actual coverage.
- `state-parity.json` — every screen's loading / empty / error / partial states mapped to parity cases or a justification; read by `test/state_parity_guard_test.dart` — when adding a screen or a state.
- `field-parity.md` — server/Web wire shapes vs Flutter reads — when adding or changing a DTO.

## Design system and UI rules

- `design-tokens.md`, `design-dimensions.md`, `design-dimensions.json` — token pipeline and shared dimension contract — when changing `raft_ui` tokens or sizes.
- `component-recipes.md` — generated component recipes (`tool/recipes`) — never edit by hand.
- `ds-migration.md` — `lib` to `raft_ui` migration map used by `tool/ds-audit` — when the design-system audit complains.
- `glyph-mapping.md` — Lucide/Material icon mapping (generated inputs for `tool/gen-glyphs`) — when adding an icon.
- `close-affordances.md`, `tap-targets.md`, `navigation-audit.md` — registries pinned by tests (close surfaces, tap targets, navigation) — when adding a surface.
- `status-bar.md`, `desktop-title-bar.md`, `android-cjk-control-typography.md`, `theme-flash.md`, `custom-app-icons.md` — platform chrome and typography rules — when touching those areas.
- `auth-keyboard.md`, `keyboard-repro.md`, `login-acceptance.md` — soft keyboard and login/onboarding rules and QA — when touching auth screens or IME insets.
- `widget-acceptance.md`, `current-acceptance.md`, `mobile-navigation.md`, `action-card-feasibility.md` — acceptance matrices read by guards and the report — when claiming component or navigation coverage.
- `diagram-font-provenance.json`, `inter-font-provenance.json` — provenance of derived fonts — when regenerating fonts.
- `space-font-provenance.json` — revision and sha256 of the bundled Space Grotesk / Space Mono — when refreshing the Raft Design System fonts.
- `desktop-cases.json`, `parity-reference-defects.json` — inputs of `tool/desktop-parity` and `tool/parity` — when adding a desktop case or known defect.
- `theme-tokens/` — theme token JSON read by `tool/gen-tokens` — when changing theme colors.
- `theme-contract.md`, `theme-contract/` — the theme contract (P0): colour roles, numeric tokens, structural options, the theme-package format and the three built-in themes' values (appendix generated by `tool/theme-contract/dump_theme_values.py`, checked by `tool/tests/test_theme_values.py`) — before adding a theme, a token or a style option, or when changing anything a theme can set.
