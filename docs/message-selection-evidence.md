# Selected-message images and forwarded snapshots

The native client now offers message selection in a channel or thread. It selects only currently loaded messages, includes loaded replies with their parent, preserves their order, and bounds each selection to 30 messages. The selection replaces the composer. Escape and Android Back first leave selection mode. Closing the image review preserves selection; completing a real save exits it.

Image export clones the complete messages in the current theme, body font, conversation width and clock format. It retains Markdown, native Mermaid diagrams, attachment images/metadata, reaction states and thread indentation. Export mode removes message actions and diagram/attachment controls. The clone waits for authorized attachments and decoded images before rasterization. The review displays the actual generated PNG. The native save picker and Android share chooser are explicit user actions. Android chooser dismissal does not prove delivery, so it preserves review/selection. There is no public image upload or Share-to-X action.

Private PNG bytes stay in memory until a user chooses save/share. Private share-file leases are deleted on review disposal or authority loss. Generation, account, server, role, channel, thread and message visibility/content checks invalidate pending captures, reviews and saves. Archive transitions and newly granted channel capabilities preserve readable previews; actual membership/capability loss cancels them. Pending attachment waits stop immediately on revocation. The implementation bounds raster size and reports a smaller-selection request instead of attempting unbounded allocation.

Forwarded bundles render only version-1 recipient projections with known provenance states. Restricted/DM/unknown source labels are omitted. Copied author/content remain visible when the original is unavailable. Attachment views use destination projection IDs; internal source IDs and signed URLs are excluded from the presentation model. The collapsed view expands explicitly; image export includes all copied messages and removes that toggle. Snapshot references do not resolve against the destination workspace.

## Verification

- `apps/raft_flutter/test/message_export_test.dart`: four passing tests cover loaded-reply ordering, selection bounds/revocation, actual Markdown/Mermaid rasterization with PNG signature and decoded dimensions, cancellation, readable preview retention across archive/grants, and authority loss during a pending save picker.
- `packages/raft_ui/test/message_export_test.dart`: three themes at 320 logical pixels, selection/copy/review/save callbacks, cancellation preserving selection, and no layout exception.
- `packages/raft_ui/test/forwarded_bundle_test.dart`: projection strips private pointers/excluded attachments and sorts thread parents/replies; all three themes expand/collapse without exposing a restricted source.
- Actual SDK WidgetPreview interaction evidence: `reports/raft-reference/export/preview-interactions.json` in the agent workspace records six passing theme/group runs and screenshots. Browser DOM semantics activates the real SDK callbacks. This preview evidence validates pure UI callbacks, not platform clipboard, PNG rasterization or OS delivery.
- `integration_test/message_selection_flow.dart` is the standalone native helper: it sends a real message, selects it through message actions, opens the actual generated PNG, verifies signature/dimensions, captures `linux-message-selection-preview`, cancels, and verifies selection/composer behavior. The parent Linux runner reached and passed this native PNG checkpoint in its full run; Android and overall-run completion remain tracked by the parent result manifest. The helper additionally checks actual native Markdown clipboard content and waits for the toast to leave before opening review.
- OS PNG-byte save/share cancellation and private-lease cleanup are independently covered by the platform sharing lane; see `docs/sharing-evidence.md`. No OS picker is injected into the whole-app selection helper.
