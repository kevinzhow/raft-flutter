## Follow-up: real menu switch and mobile Home

This follow-up builds on Root `da7939f`, including the independently validated global chooser bridge `d8655ca`. `WorkspaceView.onSwitchServer(RaftRecord, bool replaceWithHome)` delegates real menu selection to the app root. The current-server row remains a close-only action. Other desktop rows read the target server's accepted origin/principal-scoped persisted surface, validate its server slug and preserve query/fragment; invalid or absent memory falls back to the real target server root. Mobile deliberately ignores desktop memory and replaces the current entry with `/s/:slug` Home. No server or channel record is manufactured.

Source authority is `components/ui/ServerSwitcherMenu.tsx:310–324,390–393`, `utils/serverSwitcherNavigation.ts:38–44`, and `hooks/useTabRouteMemory.ts:67–104,118–148`. `App.tsx:615–621` retires the previous workspace while the URI identifies a server different from the current server. `store/serverStore.ts:370–398,511–513` accepts the real server and clears its scoped slices; `components/layout/MainLayout.tsx:914–955` replaces a desktop server root with the first actual channel and deliberately leaves mobile Home intact.

The root publishes the accepted target URI before hydration, suspends foreground/read and native-content delivery, and prevents hydration's temporary default-channel notifications from overwriting that URI. It waits for the first Flutter route-report frame before a fast cached default-root redirect, preserving the initial desktop PUSH before the Source-derived first-channel REPLACE. An identical URI can subsequently be re-reported by Router as a replacement; this never adds another history entry. Back during the observed desktop switch restores the accepted original URI, retires the pending request and rejects the released stale channel response. Principal/session reset retires this transition. Resuming the app during a held request cannot re-enable hidden foreground read.

**Loading timing remains distinct:** this bounded root bridge waits for its existing complete controller hydration before remounting WorkspaceView. Source can mount the new server shell after its synchronous server reset while individual loaders remain pending. The held-request tests prove accepted URI and retirement, not equal loading duration or an identical new-shell first frame. Hosted/Electron server-window handshakes and native menu execution are not covered.
